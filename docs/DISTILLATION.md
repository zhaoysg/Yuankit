# 从参考库到自己的组件：蒸馏流程

这里的蒸馏是设计与工程规则提取，不训练模型，不以爬取整站替代组件开发。

## 输入与证据

Ant Design 以 6.6.3/tag 对应提交为基线；HeroUI 以 v3 分支锁定提交为基线。确切 SHA、链接、核对范围在 `references/sources.lock.json`。官方网页会更新，源码引用应带提交号。未验证页面只能标 reference，不写 reviewed。

本次较深入核对的范围是主题体系、按钮、输入框/文本域规则、Dialog/Modal 交互设计；其他组件的规范是在这些原则下独立设计，并保留后续复核入口。没有完成两家全组件源码审计、全部网页截图采集或像素差异比较。

## 四维提取

| 维度 | 记录内容 | 项目中的产物 |
| --- | --- | --- |
| 视觉 | 字号、颜色、间距、圆角、阴影、尺寸与状态变化 | Token + 组件 CSS |
| 结构 | 根元素、标签、前后缀、帮助信息、图标、内容区、底部区 | Vue render tree + slot 合同 |
| 交互 | 输入、选中、聚焦、关闭、键盘、受控值、错误/加载状态 | Vue 状态/事件 + 浏览器测试 |
| 使用规范 | 场景、参数、默认值、互斥项、限制、来源和版本 | registry + 规格 Markdown + 示例 |

## 实际处理顺序

1. 按业务使用频率确定组件，而不是全站镜像。
2. 读取官方 API、设计说明和必要源码，记录版本和许可证。截图只用于视觉核对。
3. 分开记录“两家各自怎么做”，再写“YuanKit 采用/改变/暂不实现什么”。
4. 统一自己的一组 Token 与 API；不混用两家同义参数名。
5. Vue 实现组件、状态和语义；开发同源演示。
6. 按规则写断言，验证键盘、错误、禁用、中文输入、明暗与手机表现。
7. 核对实际能力与文档，打包到可消费的库；记录限制与下一步。

## 核心取舍矩阵

| 对象 | 参考点 | YuanKit 采用 | 改变/暂不实现 |
| --- | --- | --- | --- |
| Theme | Ant Token 分层；Hero 语义样式变量 | base/mode/skin/density + Provider overrides | 自有命名和值；不加载两家主题运行时 |
| Button | variant/size/disabled/loading 与 focus/pressed 状态 | 原生 button、统一 variant、键盘、busy、前后插槽 | 不复制 Hero Tailwind CSS；无链接按钮路由适配 |
| Input | 标签/描述/错误分区与状态关系 | input + label + aria-describedby；v-model；IME；清空 | 不实现 OTP、复杂格式掩码和自动完成 |
| Dialog | 标题/描述/内容/底部；关闭与聚焦规则 | 原生 dialog + 受控 open + 焦点返回 + 嵌套滚动锁 | 不依赖 React Aria；不是全套 Modal API；须补 Safari 验证 |
| Select | 标签到值的清晰映射；键盘选项 | 原生 select、单选、禁用、错误和 placeholder | 系统面板不可逐像素复刻；搜索、多选、自定义项未实现 |

每个具体组件的视觉、结构、规则及限制见 `references/components/`，工作台也会显示登记的规格。现有规范可继续改进，但改动必须同步到实现/测试，不能把文件库变成只堆截图的素材仓库。

## 版权与安全

自有组件独立编写，未直接复制 Ant/Hero 的组件源码或 CSS；未导入 Pro 模板、品牌图标或账号内容。后续复制第三方实现时另行保留许可证、来源和修改记录，不因“蒸馏”而删除归属。参考名称仅说明来源，不表示官方关联。
